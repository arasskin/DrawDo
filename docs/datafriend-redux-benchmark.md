# Datafriend versus Redux

These are the original full-query-reevaluation measurements. The subsequent
[incremental-query comparison](datafriend-incremental-queries.md) reruns the
preserved old library and optimized engine alongside Redux with the same Dart harness.

This compares the same **application operations**, using each system naturally.
Redux is a useful lower-cost reference for synchronous state updates and derived
UI reads. It does not provide Datafriend's database transactions, query engine,
indexes or entity synchronization metadata.

## Workload

- 100 or 1,000 tasks, three unchanged stickers and a 5,000-point drawing.
- Each task has `kind`, `id`, `title`, `done` and `order` fields. Repeatedly toggle
  the first task's `done` field. This deliberately matches our existing benchmark;
  it is not a random-edit, insertion, deletion, join or many-subscriber workload.
- Three query/selector subscriptions (tasks, stickers, strokes) and one publication
  listener. **1,000 tasks means one affected task query, not 1,000 queries.**
- **Edit:** toggle, update affected state and notify synchronously.
- **Full read:** edit, obtain the whole document and consume every task's
  `id`, `title` and completion flag into a checked checksum.
- **Visible read:** edit, consume those fields for the first 15 tasks and read
  the completed-task count. Both systems scan tasks for that count; neither
  maintains an incremental counter.

Datafriend uses the real Dart `AppViews` interface, native live maps, lazy row
objects, and an AELMDB database opened with `durable: false` (`MDB_NOSYNC`).
Transactions and index/query maintenance remain in the measured operation.

Redux uses normalized `{ids, entities}` task state, with IDs initially sorted
by `order`. A `done` change retains the ID array, unchanged task objects, stickers
and drawing. The task reducer updates the known task directly; it does not run a
generic triple query. Three subscriptions compare their selected slice references
and notify only on changes. Reads use entity-adapter selectors; completion count
uses a memoized selector. No React dependency or rendering is involved.

This follows Redux's guidance on [normalized state and selectors](https://redux.js.org/tutorials/essentials/part-6-performance-normalization)
and [`createEntityAdapter`](https://redux-toolkit.js.org/api/createEntityAdapter).
We do not make Redux copy unchanged UI objects or rerun a generic query just to
match Datafriend's current costs.

## Configurations

| System | Configuration |
| --- | --- |
| Datafriend | Dart AOT, uninstrumented C++ Release library, test hooks disabled |
| Redux Toolkit | Production build, `createSlice`, default production middleware, DevTools disabled |
| Toolkit without freezing | Same Toolkit reducer and selectors, `setAutoFreeze(false)` |
| Handwritten Redux | Redux `createStore`, immutable object-spread reducer, same selectors |

Redux Toolkit **2.12.0**, Redux **5.0.1**, Immer **11.1.18**, and Reselect
**5.3.0** are pinned by the benchmark's lockfile. Dependencies are local to this
host benchmark, not added to the application. Node runs with `NODE_ENV=production`:
Redux Toolkit's [development checking middleware](https://redux-toolkit.js.org/api/getDefaultMiddleware)
is absent. Immer's separate [automatic freezing](https://immerjs.github.io/immer/freezing/)
is enabled in the default Toolkit case and explicitly disabled in the second.
The harness checks the actual frozen state and verifies that both reducers keep
the previous state unchanged.

## Measurements

Results are generated by `datafriend-benchmarks/benchmarks/run_redux.py` and recorded in
[raw timings](benchmarks/datafriend-redux.csv) and
[run metadata](benchmarks/datafriend-redux-metadata.json).

Each system/workload runs in three separate processes, with 2,000 warmup edits
followed by 3,000 timed edits per process. System/workload order rotates and
reverses across rounds. Statistics below use the median of the three process
medians; p99 values use the median of the three process p99s. Garbage collection
is allowed during measurement. Compilation, initialization and correctness
checks are outside timing. No other builds or tests run alongside measurement.

Host: macOS 26.5.1 arm64, Dart 3.11.1, Node 22.20.0 / V8 12.4.
Observed one-minute load averages were 3.21–3.83; this was not a dedicated host.

| 100 | Edit + full read | 84.125 | 14.584 | 3.875 | 2.166 |
| 100 | Edit + 15 rows + count | 48.667 | 29.167 | 18.292 | 16.459 |
| 1,000 | Edit | 253.334 | 100.500 | 2.250 | 0.500 |

| 1,000 | Edit + 15 rows + count | 277.541 | 125.750 | 21.208 | 19.250 |

**1,000-task p99, microseconds:**

For 1,000 tasks, the visible workload is **0.278 ms** in Datafriend versus
**0.126 ms** in default Toolkit and **0.021 ms** without freezing: roughly
**2.2×** and **13.1×** slower respectively. Full readback is **0.638 ms** versus
**0.115 ms** and **0.015 ms**. Datafriend remains below a millisecond in these
median measurements, but this is not parity with an optimized in-memory store.

Across rounds, Datafriend's 1,000-task visible median ranged from 276.4–280.3 µs;
default Toolkit ranged from 125.5–126.5 µs. Tails varied more: Toolkit's visible
p99 ranged from 173.6–517.7 µs, while Datafriend's ranged from 304.4–329.3 µs.
The p99 table summarizes rounds; it is not a worst-case latency guarantee.

## Interpretation and limits

- Default Toolkit's freezing pass is a substantial cost in this workload. The
  no-freeze case is a more demanding target for Datafriend than the default case.
  Turning freezing off still preserves immutable updates through Immer; it only
  removes enforcement against later accidental mutation.
- Redux knows exactly which task is being changed. Datafriend applies a database
  transaction, maintains indexes and reevaluates the whole affected task query.
  Redux's narrow update is therefore useful as an application-level target, not
  evidence that an equivalent database transaction would have the same cost.
- Datafriend's full read constructs new Dart task objects and decodes their
  fields. Redux's full read creates a list of existing task references. The
  shared native map has removed triple reconstruction, but it has not eliminated
  Dart field decoding or typed row construction.
- Redux's visible mode can cost more than its full read: it computes a completion
  count and calls the memoized per-ID selector 15 times. Its full-read mode uses
  one `selectAll` and a field-consumption loop, with no completion count.
- Dart AOT/native FFI and Node/V8 are different runtimes. These are host results,
  not mobile or browser results. Flutter/React scheduling, build/layout/paint,
  synchronous disk flush and networking are excluded. This does not establish a
  full-frame bound or measure the eventual integrated network/storage system.
- Numeric-string task IDs and repeated edits of the same first row are the
  current fixture. Do not extrapolate the tiny handwritten-reducer cost to all
  JavaScript key shapes, state layouts or workloads.

## Reproduce and validation

```sh
cd datafriend-benchmarks/benchmarks/redux
npm ci --ignore-scripts --no-audit --no-fund
cd ../../../..
python3 datafriend-benchmarks/benchmarks/run_redux.py --dart /path/to/dart
```

The runner builds a separate native Release library and Dart AOT executable,
then runs all systems sequentially. Metadata records commands, runtime/package
versions, CMake configuration, source/binary hashes and per-process load averages.

Twenty-four small validation processes cover both final toggle parities and
fixtures smaller/larger than the 15-row window. All 72 timed processes also check
task values/order, exact publication counts, unchanged drawings/stickers, and
exact read checksums. Redux additionally checks old-state immutability, unchanged
task sharing and selective subscription notifications. Dart checks that toggles
publish synchronously and that unrelated cached projections retain identity.
The new Dart benchmark passes static analysis. No application code changed.
